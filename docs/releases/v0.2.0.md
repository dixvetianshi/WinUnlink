# WinUnlink v0.2.0

新增文件夹支持及删除方式选择：默认移到回收站，可手动选择直接删除；文件夹支持递归查询占用、删除、整体替换和“停止并删除”。

- 选择或拖入文件夹，显示文件数、目录数和大小。
- 文件、文件夹和“停止并删除”均沿用当前删除方式；回收站失败不会自动改为永久删除。
- 直接删除文件夹遇到失败时报告实际进度与剩余位置。
- 用来源的完整目录树替换目标，保留来源，移除旧目标中来源没有的项目；不合并目录。
- 汇总目录内文件的占用程序并按 PID 与创建时间去重。
- 右键注册同时提供文件和文件夹入口，支持旧文件入口升级、备份及临时模式。
- 文件夹的重启按钮禁用，单文件重启删除只在直接删除模式启用。

## 下载与升级

下载 `WinUnlink-v0.2.0-windows-portable.zip` 并完整解压，双击 `WinUnlink.exe`。需要 Windows 10 / 11 和 .NET Framework 4.8 或 4.8.1，请保留同目录的 `WinUnlink.exe.config`。

**从 v0.1.1 升级后，请在新版中手动重新注册右键菜单以添加文件夹入口。** 普通启动与更新不会自动注册。要撤回菜单，点击窗口里的“移除右键菜单”或运行包内 `remove-context-menu.cmd`。

## 结果与限制

文件夹整体替换先复制来源，再把旧目标移到备份位置并提交新目录，不是原子整树交换。新目标检查或旧备份清理失败时会报告未完成和保留路径。替换旧内容和备份的清理仍为永久删除，不受回收站选择控制。直接删除文件夹失败时前面的项目可能已经删除，不能假设原树未改变。

目标或来源树含 junction、符号链接等重解析点时拒绝操作；磁盘或共享根、相同和相互包含的目录也拒绝。文件夹不支持重启排队。

Windows 10 19044、NTFS、.NET Framework 4.8 的 AnyCPU（实际 x64）和 x86 各通过 22 个文件/进程场景、16 个文件夹场景及 5 个 CLI 场景，注册表测试跳过。回收站输入校验包含在上述场景中，没有调用真实回收操作。真实回收成功或取消、双入口注册表运行、后续恢复与备份清理失败、Windows 11、网络文件系统及单文件重启执行尚未验证。

直接删除不进入回收站，停止占用程序可能丢失未保存的工作。独占句柄和映射限制仍可能阻止操作，无法保证保持所有占用程序运行时完成删除或替换。
