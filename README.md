# WinUnlink

Windows 文件与文件夹的占用查询、删除和替换工具，提供中文桌面窗口及可选右键菜单。

支持移到回收站或直接删除，默认使用回收站。直接删除允许共享删除的文件时，可保留占用程序运行；独占占用可通过“停止并删除”结束相关程序后自动处理。WinUnlink 使用 Windows 官方接口独立实现，无需内核驱动，不保证对所有占用实现 Linux `unlink` 的旧句柄保留行为。

## 下载与运行

从 [GitHub Releases](https://github.com/dixvetianshi/WinUnlink/releases) 下载 `WinUnlink-v0.2.0-windows-portable.zip`，完整解压后双击 `WinUnlink.exe`。请让 `WinUnlink.exe.config` 始终与程序位于同一目录，不要只复制 EXE。

- 运行环境：Windows 10 / 11，.NET Framework 4.8 或 4.8.1。
- 默认构建为 AnyCPU，在 64 位 Windows 上运行 64 位进程。
- 解压和普通启动不会安装右键菜单、驱动或服务，也不会登记重启任务。
- ZIP 附带 `SHA256SUMS.txt`，可用 `Get-FileHash -Algorithm SHA256` 检查文件摘要。

实际验证环境为 Windows 10 19044、NTFS、.NET Framework 4.8；Windows 11 尚未进行实机验证。具体结果见 [验证说明](docs/verification.md)。

v0.2.0 的 AnyCPU（实际 x64）和 x86 各通过 22 个文件/进程场景、16 个文件夹场景及 5 个 CLI 场景。注册表测试跳过；回收站输入校验通过，但真实回收操作尚未验证。

## 使用方法

1. 点击“选择目标…”选择一个文件或文件夹，也可将它拖入窗口。点击“查询占用”查看进程名称、PID 和程序路径；文件夹会同时显示递归文件数、目录数和大小。
2. 选择删除方式：默认移到回收站，需要永久移除时选择直接删除。点击“删除目标”，执行前弹窗显示方式、目标范围与查询到的占用程序；文件夹操作包含其中全部内容。
3. 独占占用阻止删除时，点击“停止并删除”。确认窗口标明将停止的程序及 PID；确认后结束全部可处理的占用程序，并按当前删除方式处理目标，无需先勾选或再点删除。
4. 替换时先查询目标，再点击“选择来源…”选择同类型的来源文件或文件夹，最后点击“替换目标”。来源保持保留。需要结束占用者时，可勾选进程并点击“结束选中进程”，再重试替换。

直接删除不会进入回收站。“停止并删除”和“结束选中进程”可能丢失占用程序尚未保存的工作。系统关键进程、服务、会话 0 和其他用户会话的进程不会在此结束；停止失败会显示逐个结果并跳过删除。

回收站操作失败时会保留失败结果，**不会自动改为直接删除**。网络路径或存储位置不支持回收站时，请核对结果；需要永久删除必须手动选择该方式。

文件夹占用查询注册其中的文件并递归汇总进程，以 PID 和创建时间去重。空文件夹、程序工作目录、目录句柄或驱动占用仍可能未被报告；零条结果不能证明没有占用。

## 文件夹替换与未完成结果

文件夹替换是**整体替换**：目标最终使用来源的完整目录树，旧目标中来源没有的文件和空目录也会移除，不进行文件合并。删除方式不改变替换流程；**替换对旧内容及旧备份的清理仍是永久删除，不送入回收站**。目标和来源必须是两个独立目录，不能相同或互相包含，包括实际路径别名。

提交前先把来源完整复制到目标同级的临时目录，再把旧目标移到备份位置，最后把准备的新目录移到目标路径。来源保持保留。这不是原子的整树交换，两次重命名之间目标路径可能短暂不存在；如果新目录提交失败，工具会尝试恢复原目录。

新目标检查或旧备份清理失败时，会报告“未完成”并显示保留路径；此时新目录可能已在目标位置，旧内容可能仍在备份目录。请按结果检查目标与保留目录，不要把未完成结果当成未发生操作。恢复失败分支尚未经过真实故障注入。

选择直接删除文件夹时会逐项执行：遇到占用或权限问题，前面的项目可能已经删除，结果会报告实际移除数量与剩余位置，不会自动还原已删内容。

普通文件替换仍使用同目录临时文件与重命名提交，不会先清空原目标。新文件和新目录继承所在父目录的权限，不克隆旧目标的自定义 ACL、时间或只读属性。实现细节见 [实现说明](docs/implementation-notes.md)。

## 可选右键菜单

在窗口底部点击“注册右键菜单”，工具会先显示变更计划，同时添加当前用户的文件和文件夹入口：

- `HKCU\Software\Classes\*\shell\WinUnlink.FileTools`
- `HKCU\Software\Classes\Directory\shell\WinUnlink.FileTools`

Win10 使用普通右键菜单；Win11 从“显示更多选项”进入。菜单打开工具并查询目标，删除或替换仍需确认。**从 v0.1.1 升级后，需要在新版中手动重新注册，才会补上文件夹入口**；启动或更新程序不会自动修改菜单。文件夹入口用于右键点击目录本身，不是空白处菜单。

重复注册保持幂等，升级旧文件入口时保留原备份，并为新增文件夹入口保存备份。普通模式的备份位于 `%LOCALAPPDATA%\WinUnlink\backups`。移除菜单会处理两个入口并保留备份；如果任一入口存在用户修改、所有权冲突或无效备份，工具会保留现有配置并说明原因。

需要临时入口时，在解压目录运行：

```powershell
.\WinUnlink.exe --install-menu-temporary --yes
```

两个临时菜单及其命令子项都使用内存中的 Volatile 注册表键，随用户注册表 hive 卸载而消失，通常注销后失效，真正重启会清除。关闭工具窗口不会移除菜单。临时模式备份位于程序旁的 `temporary-menu-backups`。

可在窗口中点击“移除右键菜单”，或双击便携包根目录的 `remove-context-menu.cmd`。源码构建的撤回脚本为 `scripts/立即移除右键菜单.cmd`。已有普通模式与临时模式不会互相自动转换，需要先移除再注册。

## 重启后处理

“重启后删除”和“重启后替换”目前**只支持单个文件**，需要管理员权限和可确认的本地磁盘路径。“重启后删除”只在选择直接删除时启用，回收站模式不会登记永久删除任务；重启替换属于替换操作，不受删除方式选择控制。选中文件夹时两个按钮均禁用，工具不会登记递归目录重启任务，也不会自动重启计算机。

排队成功仅表示 Windows 接受了请求，不表示文件已经删除或替换。重启后仍须检查结果。重启替换会预先准备目标同目录的临时文件，请保留结果显示的文件；重启前不要移动或替换目标，启动队列按路径执行。

## 从源码构建

在项目目录打开 PowerShell：

```powershell
.\build.ps1
.\test.ps1 -CompileOnly
```

使用 Windows 自带的 .NET Framework C# 编译器，无 NuGet 包，不需要 .NET SDK、Node.js 或 Java。程序输出到 `artifacts/bin`。可用 `build.ps1 -Platform x86` 或 `-Platform x64` 指定架构，也可用支持 .NET Framework 4.8 的 Visual Studio 打开 `WinUnlink.csproj`。

生成与 Release 相同布局的便携包：

```powershell
.\scripts\package-release.ps1
```

ZIP 和归档 SHA-256 输出到 `artifacts/releases/v0.2.0`。默认构建不包含调试路径；开发时需要调试符号可运行 `build.ps1 -IncludeDebugSymbols`。

执行文件、文件夹与 CLI 测试：

```powershell
.\test.ps1
.\test.ps1 -Platform x86
```

夹具位于项目 `artifacts/**/cases/<GUID>`，只操作自建文件和测试子进程，默认跳过注册表测试。注册表检查仅供隔离的 Windows 沙盒或虚拟机中人工运行，必须显式传入 `-AllowRegistryTests`。底层系统探针位于 `tests/probe.ps1`。

## 命令入口

```powershell
.\WinUnlink.exe --inspect 'C:\work\target.dll'
.\WinUnlink.exe --scan 'C:\work\target-folder' --report 'C:\work\scan.json'
.\WinUnlink.exe --install-menu --yes --report 'C:\work\menu-install.json'
.\WinUnlink.exe --uninstall-menu --yes --report 'C:\work\menu-remove.json'
```

上述命令适用于便携包目录；源码构建时将程序路径改为 `.\artifacts\bin\WinUnlink.exe`。扫描支持文件与文件夹，JSON 包含目标类型、数量、进程名称、PID、创建时间和操作限制。报告文件必须尚不存在。菜单命令没有 `--yes` 时只返回计划；删除与替换在窗口内确认。

## 兼容性与限制

- 每次处理一个普通文件或文件夹，拒绝设备路径、NTFS 备用数据流、磁盘根目录和 UNC 共享根目录。
- 最终目标或来源为重解析点时拒绝；文件夹树包含 junction、符号链接或其他重解析点时在操作前拒绝，不遍历其外部内容。
- 独占句柄、权限和运行中的可执行映像仍可能阻止操作。管理员权限不会绕过共享锁或全部映射限制。
- 文件夹整体替换需要同级临时目录的空间，旧备份可能因占用未能清理。请检查未完成结果显示的路径。
- Windows 11、网络共享、其他文件系统、文件重启队列执行，以及目录恢复失败分支尚未进行真实验证。
- 回收站处理路径已提供，但没有在实际回收站执行验证；永久删除测试结果不能作为回收站成功的证明。

本项目不依赖或分发 IObit Unlocker 的二进制、驱动或反编译源码。参考来源见 [实现说明](docs/implementation-notes.md)。
